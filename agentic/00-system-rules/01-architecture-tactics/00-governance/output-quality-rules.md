# Output Quality Rules

- Clarity comes before completeness and cleverness.
- Each file must have an obvious purpose and a stable structure.
- Business rules must be testable and written as concrete statements.
- API files must remain transport-focused and must not redefine domain logic.
- Structured files must stay machine-readable and deterministic.
- Cross-module behavior must name the port, facade, or query service that mediates the interaction.
