# Knowledge Sync

This workflow extracts production-grade knowledge from finalized Artifacts (`005.Develop.002.Artifacts`) and syncs them into the searchable Knowledge Base (`006.Knowledge`).

> **IMPORTANT:** Artifacts are DRAFTS. Knowledge is PRODUCTION. This Skill should only be triggered when artifacts have been reviewed and approved.

- **INPUT SOURCE FILES**
  - **CONVENTIONS**
    - `003.Setup.003.Source Mapping Instructions/001.00 Common/001.00.01 Artifact Code Prefix Convention.md`
    - `003.Setup.003.Source Mapping Instructions/001.00 Common/001.00.02 Artifact Versioning Convention.md`
  - **KNOWLEDGE INDEX**
    - `006.Knowledge/_index/manifest.json`
    - `006.Knowledge/_index/by-component.json`
    - `006.Knowledge/_index/by-feature.json`
    - `006.Knowledge/_index/by-keyword.json`

- **GENERATION RULES**
  - VALIDATE the REQUEST CODE (Folder Name) in `005.Develop.002.Artifacts`.
    - If the request code is NOT FOUND, STOP and INFORM user that "REQUEST NOT FOUND".
  - Read `006.Knowledge/_index/manifest.json` to understand the current knowledge landscape.
  - Scan ALL artifact files under `005.Develop.002.Artifacts/${REQUEST CODE}/` and SYNC each one to the corresponding Knowledge folder using the mapping below.

- **ARTIFACT-TO-KNOWLEDGE FOLDER MAPPING**

  | Source Artifact | Knowledge Folder | Decomposition Strategy |
  |---|---|---|
  | `001.Requirement Development Workflow/End User Requirement.md` | `001. End User Requirement` | 1 file (whole document with metadata header) |
  | `001.Requirement Development Workflow/Information Collection.json` | `002. End User Information Collection` | Each JSON array item → 1 file |
  | `001.Requirement Development Workflow/Business Requirement Document.md` | `003. Business Requirement Document` | Split by section → 4 files (scope, functional, rules, constraints) |
  | `002.Technical Requirement Workflow/System Context Information.md` | `004. System Context Information` | Split by section → 5 files (tech-stack, db, patterns, infra, registry) |
  | `002.Technical Requirement Workflow/Additional System Information.json` | `005. Additional System Information` | Each JSON array item → 1 file |
  | `002.Technical Requirement Workflow/Functional Requirement Document.md` | `006. Functional Requirement Document` | Split by section → 4 files (scope, requirements, behavior, constraints) |
  | `002.Technical Requirement Workflow/Additional Functional Information.json` | `007. Additional Functional Information` | Each JSON array item → 1 file |
  | `002.Technical Requirement Workflow/Function Specifications.json` | `008. Function Specifications` | 2 files (JSON registry + MD human-readable) |
  | `003.Software Architecture Workflow/API Tactic Architecture.json` | `009. API Tactic Architecture` | Each Vertical Slice → 1 file |
  | `003.Software Architecture Workflow/Flow Sequence Architecture.md` | `010. Flow Sequence Architecture` | Each Mermaid diagram → 1 file |
  | `003.Software Architecture Workflow/Strategic Architecture.md` | `011. Strategic Architecture` | Split by C4 level → 2 files (system-context, container) |
  | `003.Software Architecture Workflow/UI Component Architecture.json` | `012. UI Component Architecture` | Split by Atomic level → 5 files (atoms, molecules, organisms, templates, pages) |
  | `003.Testing Requirement Workflow/Test Cases.json` | `013. Test Cases` | Each JSON array item → 1 file |
  | `003.Testing Requirement Workflow/Test Checklist.json` | `014. Test Checklist` | Each JSON array item → 1 file |
  | `003.Testing Requirement Workflow/Test Impact.json` | `015. Test Impact` | Each JSON array item → 1 file |
  | `003.Testing Requirement Workflow/Test Scope.json` | `016. Test Scope` | Each JSON array item → 1 file |
  | `003.Testing Requirement Workflow/Test Steps.json` | `017. Test Steps` | Each TES-CAS group → 1 file |

- **FILE NAMING CONVENTION**
  - Pattern: `${REQUEST CODE}.${ARTIFACT_CODE}.${descriptive-slug}.{json|md}`
  - Examples:
    - `AIPD-000002.end-user-requirement.md`
    - `AIPD-000002.INF-000001.fiscal-calendar-boundaries.json`
    - `AIPD-000002.SLICE_01.export-module.json`
    - `AIPD-000002.TES-000001.CAS-000001.date-range-365.json`

- **METADATA HEADERS**
  - **Markdown files**: Include HTML comment block at top:
    ```
    <!-- Knowledge Metadata
    Feature-Code: ${REQUEST CODE}
    Feature-Name: ${FEATURE NAME}
    Source-File: ${relative path to source artifact}
    Source-Version: ${version from artifact}
    -->
    ```
  - **JSON files**: Include `_metadata` object:
    ```json
    {
      "_metadata": {
        "featureCode": "${REQUEST CODE}",
        "featureName": "${FEATURE NAME}",
        "sourceFile": "${relative path to source artifact}",
        "sourceVersion": "${version from artifact}"
      }
    }
    ```

- **INDEX UPDATE RULES**
  - After syncing ALL knowledge files, update `006.Knowledge/_index/`:
    - `manifest.json`: Add/update feature entry with components, tech stack, business rules, API endpoints, knowledge categories, and file counts.
    - `by-component.json`: For EACH architectural component mentioned in the artifacts, map it to the list of knowledge files that reference it.
    - `by-feature.json`: Map the REQUEST CODE to ALL knowledge files, categorized by `what-we-build`, `how-we-build`, `how-we-test`, `what-can-break`.
    - `by-keyword.json`: Extract significant keywords (technology names, business terms, patterns) and map each to its referencing files. Include `aliases` array for semantic search support.

- **VERIFICATION**
  - After sync, run a file count verification: `find "docs/006.Knowledge" -type f | wc -l`
  - Spot-check 2-3 keyword searches (e.g., grep for a component name) to confirm searchability.
  - Report the total files created and any keywords indexed.
