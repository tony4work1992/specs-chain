# Defect Lifecycle

## States

- `REPORTED`
- `TRIAGED`
- `CONFIRMED`
- `IN_PROGRESS`
- `FIX_READY`
- `VALIDATING`
- `RELEASED`
- `CLOSED`

## Flow

1. Report the defect with evidence and impact.
2. Triage severity, owner, and next action.
3. Confirm the defect and define the fix scope.
4. Implement and test the fix.
5. Validate in the target environment.
6. Release through the standard or hotfix path.
7. Close with references to root cause and release version.

## Required Links

- bug report
- related API or feature docs when applicable
- fix PR or change set
- release or hotfix reference
