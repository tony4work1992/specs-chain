# Incident Response

## Purpose

Create a repeatable response for live-service failures and major degradations.

## Core Roles

- incident commander
- communications owner
- primary investigator
- supporting engineers

## Response Flow

1. Acknowledge the incident and create a shared coordination channel.
2. Assign an incident commander.
3. Stabilize user impact first.
4. Identify likely scope, blast radius, and affected services.
5. Mitigate, roll back, or degrade safely as needed.
6. Confirm recovery with monitoring and smoke validation.
7. Open postmortem follow-up.

## Principles

- optimize for fast shared understanding
- communicate what is known and unknown
- prefer safe recovery over premature root-cause certainty
